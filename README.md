# Luxury Car Rental Dubai

A custom Next.js 15 site for a Dubai supercar and luxury vehicle rental business.
No payments are taken online — every booking is submitted as a fully populated
WhatsApp message.

## Stack

| Layer | Choice |
| --- | --- |
| Framework | Next.js 15 (App Router), React 19, TypeScript |
| Styling | Tailwind CSS v4 (`@theme` tokens in `src/app/globals.css`) |
| Animation | GSAP + ScrollTrigger, Lenis smooth scroll |
| Type | Haymila (display), Qiswah (accent), Inter (body) |
| Data | Static `data/fleet.json`, regenerated by an import script |
| Images | 803 files served from `public/fleet/` - nothing is hotlinked |
| Booking | `wa.me` deep link — no backend, no payment processor |

## Ports

This project is pinned to **port 3100** in `package.json` (`next dev -p 3100`,
`next start -p 3100`). It never uses 3000, which is reserved for another site on
this machine. Do not change this.

## Getting started

```bash
npm install
cp .env.example .env.local   # then set your WhatsApp number
npm run dev                  # http://localhost:3100
```

### Required configuration

`.env.local`:

```
NEXT_PUBLIC_WHATSAPP_NUMBER=971501234567   # digits only, no + or spaces
NEXT_PUBLIC_SITE_NAME="Luxury Car Rental Dubai"
NEXT_PUBLIC_SITE_URL=https://yourdomain.com   # http://localhost:3100 for local
```

Until a valid number is set, the booking form and contact page show a
configuration notice instead of a send button, and the floating WhatsApp button
is hidden.

## The fleet data

`data/fleet.json` holds 119 cars and is generated from the legacy WooCommerce
catalogue:

```bash
npm run refresh:fleet     # import + download images
```

That runs two steps, which can also be run separately:

```bash
npm run import:fleet      # rewrites data/fleet.json from the source API
npm run localise:images   # downloads images, repoints fleet.json at local files
```

The importer (`scripts/import-fleet.mjs`) reads the public Store API, then:

- merges the legacy site's duplicate per-day and per-month listings of the same
  car into one record with a `pricing` block,
- derives brand and body type from the category taxonomy,
- collects colour variants from the `Color` attribute,
- parses engine, power, torque, 0–100 km/h and top speed out of the
  description prose,
- de-duplicates images across the merged listings.

`scripts/localise-images.mjs` then downloads every photograph to
`public/fleet/<slug>/` and rewrites the JSON to local paths. It is resumable:
files already on disk are skipped, downloads land via a `.part` temp file so an
interrupt cannot leave a truncated image, and a failed download keeps its remote
URL rather than producing a 404. Pass `--force` to re-download everything.

**Run the two in that order.** `import:fleet` writes remote URLs back into
`fleet.json`, so running it alone re-introduces hotlinking until
`localise:images` follows. `npm run refresh:fleet` does both.

Both scripts overwrite `data/fleet.json` wholesale, so hand-edits to that file
will be lost — change the importer instead.

### What the source data does *not* contain

- **Seat counts.** The descriptions mention "sport seats" but never a number, so
  there is no `seats` field. Add it manually if you want to filter by capacity.
- **Complete specs.** Coverage is partial: engine 63/119, power 65/119,
  0–100 km/h 90/119, top speed 66/119. The UI only renders the fields a given
  car actually has.
- **Per-colour pricing or photography.** Colours are a flat list per car.

## Booking flow

1. Visitor picks a car, colour, basis (daily/monthly), dates and location.
2. `src/lib/whatsapp.ts` builds a plain-text enquiry containing the vehicle,
   colour, advertised rate, dates, computed duration, estimated total, pick-up
   location, the customer's contact details, notes, and a link back to the
   listing.
3. Submitting opens `wa.me/<number>?text=…` in a new tab. The visitor presses
   send in WhatsApp; nothing is stored server-side.

The form has a **Preview message** disclosure so you can see the exact text a
customer will send.

Because this is a `wa.me` link, the message is composed in the customer's own
WhatsApp — they can edit it before sending, and you receive it from their
number. There is no delivery receipt on the website side.

## Before going live

These are outstanding and need a decision:

1. **Font licensing.** Haymila and Qiswah are 1001Fonts *Free For Personal Use*.
   Commercial use requires written permission from each author. See
   `src/fonts/*-eula.txt`. Either license them or substitute.
2. **Image rights.** The photography was taken from the source catalogue. It is
   now served from this repo rather than hotlinked, but that does not by itself
   grant you a licence to it — confirm you own or are licensed to use these
   images.
3. **Content is placeholder** where it states policy: mileage allowances, age
   limits, deposit terms and opening hours in `/services` and `/contact` are
   plausible defaults, not your actual terms. Replace them.
4. **Google Fonts at build time.** Inter is fetched from Google during
   `next build`. If your build environment blocks that, self-host Inter the same
   way Haymila and Qiswah are handled in `src/app/layout.tsx`.

## Images

803 photographs, ~108 MB, committed to the repo so deployment needs no external
host. `next.config.ts` sets `remotePatterns: []` — no remote image host is
permitted, so an accidental hotlink fails loudly at build time instead of
silently depending on someone else's server.

Originals are ~1600px and median ~130 KB. `next/image` negotiates format per
request: a 197 KB source file is served as 40 KB AVIF to browsers that accept it.
